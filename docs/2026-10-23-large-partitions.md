# 大分片与细粒度恢复

最终目录大小和内存/恢复批次分别配置。旧默认仍是每最终分片 500 区块、每 checkpoint 500 区块。需要减少最终小文件时，可在新 run 的配置中选择：

```toml
blocks_per_partition = 100000
blocks_per_checkpoint = 500
```

`blocks_per_partition` 必须是 1–100000 的整数，属于不可变 run 身份。已有 run 保持原值；改变最终大小须使用新 run ID。`blocks_per_checkpoint` 必须是 1–5000 的整数，是运行参数；停掉已确认的采集 PID、等待退出后，可调整 checkpoint 频率恢复原 run。布尔值、小数、越界值均拒绝，日志明确指出配置名和范围。旧 manifest 无此运行字段时采用 500，其身份哈希不变。旧数据不迁移、不合并、不重命名，两种最终目录布局继续支持。

## 文件与恢复生命周期

协调线程只保留一个规范化 checkpoint 批次，到配置区块数或估算 Arrow payload 64MiB 时在完整区块边界发布。估算按新增区块计算；单块、Python 对象开销和最多 `2 * concurrency` 个预取结果额外占用内存，不能把 64MiB 当作 RSS 上限。

当前未完成的最终分片在 run 的隐藏 `.staging/` 下写入私有 fragments。只有四张 Parquet 表及校验元数据全部关闭、fsync 并原子发布后才算 durable。未关闭的文件、pending 临时目录、损坏/重叠/有间隙的后缀都不作为可信进度；恢复只重用从最终分片起点开始、身份/范围/schema/校验和都有效的最长连续前缀。私有 fragments 不进入最终分片发现、报表或质量覆盖。

最终范围齐备后按最多 4096 行批次读 fragments，写四个最终 Zstandard Parquet 文件和 `_partition.json`，关闭/同步并原子发布 `data/YYYY-MM-DD/START-END/`。校验最终文件、记录现有 SQLite completion 后才清理 fragments。完整前缀在合成中断后可从磁盘重放，不需重新请求 block/receipt；最终目录已发布但 SQLite 未记完成时先校验恢复该目录。已完成历史分片继续复核并跳过。

同一 run 只允许一个写入进程。默认 SIGTERM 仍可立即退出，不保证补刷未完成批次；恢复可能重取当前未持久化批次和有界预取请求。已发布 fragments 保留。RPC/规范化/写入出错会取消排队工作、等待在途线程退出，丢弃未完成内存批次。不要手工删除 `.staging` 来“清理缓存”。损坏的最终目录重写仍保留隐藏 `.replaced-*` 备份。

## 进度与临时空间

- `processed_blocks`：本次规范化、复核最终分片及重用 prefix 的总区块数。
- `committed_blocks`：已验证并完成 SQLite 记录的最终分片区块数。
- `durable_blocks`：可信 fragments 与最终分片已持久化的区块数。
- `reused_blocks`：本次从 fragments 恢复的 prefix；`rpc_blocks_avoided` 还包含已跳过的最终分片。
- `new_blocks`、速率与 ETA：仅本次新请求/规范化区块参与速率，不把磁盘恢复算成新 RPC 吞吐。ETA 是扫描估计，不含未来合成、校验和分析阶段。

每次 checkpoint 有进度，最终合成另记实际开始/结束及耗时，完整性校验也独立记录。未完成 checkpoint 内仍在完整区块边界约每 30 秒报告；阻塞 RPC/大块/磁盘操作可延迟日志。

100000 区块、checkpoint 500 且未触发提前字节刷新的情况下，一个活动最终分片约有 200 组临时 fragments。提前字节刷新可产生更多组。合成期间 fragments 与最终临时输出同时存在；这会增加临时磁盘写入和一次流式读取/重写，不承诺更快磁盘或零拷贝。完成后最终仍为四个 Parquet 加一个元数据文件。按区块数计算，100000 区块从 500 改为 100000 时最终目录由 200 个变为 1 个、最终文件由 1000 个变为 5 个；这是文件数量算术，实际空间/吞吐以实测为准。

质量检查按类型化 Arrow 批次做物理检查，DuckDB 用 512MB 内存预算及磁盘 spill 做跨表/跨分片关系检查；该预算不等于总进程 RSS，也不免除临时空间/CPU 成本。质量失败仍阻止最终分析/报告。

## 离线复现

小型 smoke（两个 workload、三种独立子进程运行，包含中断恢复）：

```bash
PYTHONPATH=src python tools/benchmark_partitions.py --blocks 12 --checkpoint-blocks 2 --interrupt-after 5
```

验收规模命令，输出目录须是新的空目录以保留可检查的数据：

```bash
PYTHONPATH=src python tools/benchmark_partitions.py --blocks 100000 --output-directory /tmp/opbnb-partitions-100000 > /tmp/opbnb-partitions-100000.json
```

也可用 `--mode representative` 或 `--mode empty` 单独运行。默认 checkpoint 500、在第 1250 个规范化区块之后模拟异常中断；100000 大分片恢复应避开前 1000 个 durable 区块的 block/receipt RPC（2000 个请求元素）。不足中断位置的小型输入不运行恢复对比，JSON 的 `interrupted_resume` 为 null。

生成器只保存随包六块 fixture 模板，按编号即时生成独特 block/transaction 哈希、合法父哈希/索引/时间戳；representative 模式保留模板交易/日志/精确长整数/未知费用，empty 模式生成空块。没有整链 Python 字典，不接受生产节点 URL。500 和 100000 最终大小各自从新进程启动，恢复实验再用单独进程，避免其他 workload 的峰值 RSS 污染。

只有质量通过、精确预期行数一致、四张表按物理有序行生成的 SHA256 指纹完全相同才报告比较成功。指纹每次最多转为 Python 4096 行，不调用 `Store.read_table`。JSON 包含最终目录/Parquet/总文件数、私有 staging 与 data 的逻辑磁盘峰值、采集/最终合成/校验/指纹耗时及进程峰值 RSS；RSS 在 Darwin 按字节、Linux 按 KiB 转字节。采集耗时包含合成，合成耗时另列便于理解，不能直接相加；恢复运行采集耗时还含中断前工作和恢复复核。进程 RSS 包括校验/指纹阶段，耗时不含 Python 启动/导入；磁盘每 50ms 采样并在 fragment/合成事件补样，仍可能漏掉短暂峰值，采样自身也有开销。逻辑磁盘大小不等于文件系统分配空间，未计 DuckDB scratch、SQLite WAL 或系统页缓存。

合成 fixture 的 calldata/receipt 很小，这些测量不代表主网负载、节点容量或 16GB 主机可承载三个月数据。正式生产评估应先用独立 run 做一天样本，测实际块大小、临时 I/O、吞吐和峰值 RSS。本说明不把合成实验当作生产容量证明。

## 2026-10-23 集成验收结果

Python3.12，完整离线测试 **327 passed**，编译检查通过。存储、校验、采集/基准各自完成独立审查；审查发现的非对象 JSON 片段元数据恢复错误已先以12个失败用例复现，再修复并复审。旧 identity、旧布局及已有分片不迁移。

实际运行上述 **100000 区块、两种 workload、六个隔离子进程** 验收，而非用六块 fixture 代替规模测试。代表性模式包含183334交易、183334回执、33334日志；空块模式各有100000区块、零交易/日志。三种运行的完整质量、行数及四表物理有序 SHA256 指纹均一致。

| workload/最终分片 | 最终目录/文件数 | 采集秒数 | 其中最终合成秒数 | 校验秒数 | 进程峰值 RSS MiB |
| --- | --- | --- | --- | --- | --- |
| 代表性交易，500区块 | 200 / 1000 | 38.71 | 4.95 | 1.44 | 242.86 |
| 代表性交易，100000区块 | 1 / 5 | 38.31 | 1.08 | 0.75 | 267.83 |
| 代表性交易，100000区块中断恢复 | 1 / 5 | 36.21 | 1.02 | 0.77 | 274.56 |
| 空块，500区块 | 200 / 1000 | 11.10 | 3.79 | 0.98 | 146.53 |
| 空块，100000区块 | 1 / 5 | 12.00 | 0.54 | 0.48 | 145.36 |
| 空块，100000区块中断恢复 | 1 / 5 | 11.97 | 0.40 | 0.33 | 145.67 |

采集时间包含合成阶段；列出的两项不能相加。恢复时间还包括中断前工作及恢复校验。时间测量有调度、文件系统缓存和磁盘采样开销，不能用一次约1%的差异宣称性能提升。大分片主要实现文件数减少200倍；空块示例采集反而略慢。

两种恢复运行均在1250个规范化区块后模拟中断，重启复用1000个已持久化区块，从区块1100开始请求（本实验起始区块100），避开2000次模拟 block/receipt 调用，最终无漏采、重复及遗留 staging 文件。实际程序中未落盘批次和有界预取仍可能需要重采。

代表性大分片私有 staging 逻辑磁盘峰值约7.45MiB，最终数据约6.46MiB；空块相应约2.40/1.39MiB。二者在最终发布时可能同时占用空间，另需考虑已完成分片、隐藏备份、DuckDB scratch、SQLite WAL 和系统开销。单块/实际 calldata 变大时内存与临时空间也会增长，本次未验证真实主网三个月规模或16GB资源上限。
