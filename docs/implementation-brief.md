Implement the previously approved standalone code design, phases A-C, in `opbnb-activity/` under this brief's parent directory. Do not access or change the opbnb/op-geth repositories. No git commits or branches. Use apply_patch for source edits. Read the local TDD skill and demonstrate meaningful red-green tests. No live node URL is supplied or required. Do not attempt chain data collection.

## Scope and architecture

- Python >=3.11, httpx, PyArrow Parquet, DuckDB, SQLite, pytest, Matplotlib. Use the Python environment `/private/tmp/opbnb-activity-venv` if prepared by controller. Configuration TOML, RPC endpoint via OPBNB_RPC_URL. Node URL required only for probe and collect.
- Provide a real runnable CLI with `probe`, `collect`, `validate`, `analyze`, `report`, plus an explicit offline `demo` command. Add pyproject, config.example.toml, Chinese README with server/nohup instructions, and meaningful tests/fixtures. Example results must visibly say synthetic/test data, never claim mainnet results. No extra deployment service.
- Files: src/opbnb_activity/{__init__,__main__,cli,config,models,rpc,probe,block_range,collect,checkpoint,storage,decode,labels,metrics,quality,report}.py and sql/{daily,contracts,projects,senders,retention}.sql. Reasonable simplification of interfaces is allowed with concrete documented rationale; do not create empty module stubs. Prefer a small complete vertical slice to silent fake analytics.
- Date window defaults to Asia/Shanghai 2026-07-22 inclusive, 2026-10-22 exclusive. Save UTC timestamps, integer token values as decimal strings, never float raw uint256. Configurable windows. Per-run manifest, explicit run ID for offline commands. Different sample/full windows must not mix.
- RPC: match batch IDs independent of response order, detect missing/duplicate IDs, retry only transient/failed items, bound retries/timeouts, honor Retry-After, handle HTTP 429 and unsupported methods. Conservative 1 QPS, one concurrent HTTP request default; account for batch elements in rate budget. Do not expose endpoint/auth in error text/logs. Do not automatically increase request pressure. Use injectable HTTP transport (httpx.MockTransport) and sleep hooks in tests to avoid real network/waits.
- Probe chain ID 204 before anything costly, historical coverage, batch/receipt/log/trace support with bounded representative requests. An archive node need not support tracing. Unsupported methods downgrade capabilities; transient or pruned-data errors must not be mislabeled unsupported. Do not claim full throughput testing merely from a probe.
- Range resolver: lower-bound binary search block timestamps for [start,end), cover exact equality and irregular timestamps. Reject future/incomplete windows rather than silently truncate.
- Collection: full blocks/transactions, receipts (block method if supported, fallback to per-transaction batches). Persist typed blocks, transactions, receipts, logs in deterministic Parquet partitions plus SQLite per-run task status. Resume must verify existing completed output, handle crash between final write and checkpoint, and avoid double counts. Missing/mismatched receipt must prevent completion. Normalize fields. Completed tasks tied to config/run window. Store actual block end-exclusive range and exact window in manifest. Verify chain continuity, counts and hashes. Unknown fee components remain null.
- Labels: CSV address/project/category/role/source_url/confidence/valid block ranges, optional manual labels. Project main rank by direct call (one tx at most one project), separately retain unknown. Dedup after grouping contracts to projects. User deposit must not be classified as system merely due type 0x7e; use explicit known protocol L1 attributes recipient combined with transaction type (mark/configure address) and conservative unknown handling. Do not call every empty-input address an EOA without historical code evidence; retain unknown when needed.
- Analytics: daily tx success/failure/system, successful non-system sending addresses (main active measure), all non-system sending addresses (supplement), unique whole-window/weekly/monthly addresses; top contract, project and sender tables with unknown coverage, fees coverage, concentration, D1/D7 mature cohort retention. Financial output can be restricted to successful top-level native value and explicitly verified asset Transfer logs with supplied decimals, using Decimal; no invented prices, TVL, DEX/bridge volume, bot/users estimates. State unsupported economic metrics explicitly. Failure fees included where known. ERC20 vs NFT Transfer ambiguity must not be silently conflated. Fee only calculate full total when both L1+L2 components known (or provided verified total); still retain partial L2 separately.
- Quality: missing blocks, parent hashes, tx counts, receipt joins/hashes, duplicates and manifest boundaries. Incomplete quality must prevent final report. Empty valid window results are handled coherently. Dataset path not tied to local developer filesystem.
- Reporting: CSV tables, Markdown summary, PNG trend and top projects at least. Clearly distinguish fixture vs real run. Quote metric definitions, timezone, dataset and labels versions, coverage/missing financial fields. No wallet-human equivalence or speculative attribution.
- Demo fixture: multiple dates, repeated sender across days and multiple contracts in one project, different project, failure, system tx and user deposit, huge uint256 >38 digits, unknown fees, token Transfer ambiguity and nonmature cohort. Demo can load fixture directly through the same normalizer/store/quality/metrics/report pipeline; include end-to-end test with exact expected counts and sums. Live collection mocked separately.
